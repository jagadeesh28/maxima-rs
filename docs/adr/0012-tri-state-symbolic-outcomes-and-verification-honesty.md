# Tri-State Symbolic Outcomes, Verification Honesty, and Resource Safety

**Status**: Accepted

**Context**:
An exhaustive multi-model audit revealed that `maxima-rs` previously exhibited misleading verification badges (e.g. hardcoding `verified = Some(true)` on incorrect ODE and definite integral outputs), conflated unimplemented features with theoretical impossibility (e.g. claiming "no elementary antiderivative found" for integrands lacking support), silently mutated mathematical inputs via inverted parser operator precedence (`-x^2` parsing as `(-x)^2`), and aborted the entire server process via stack overflow on deep AST nesting (`3000` parentheses).

To achieve industrial reliability and absolute truthfulness in mathematical results, we decided to:
1. **Enforce Tri-State Symbolic Domain Outcomes**: CAS operations that may fail to find a closed form (such as integration and limit calculation) must return a structured tri-state enum:
   - `Solved(Expr)`: An exact analytical closed-form was derived.
   - `ProvenNonElementary`: The algorithm formally proved that no elementary closed form exists in the differential/asymptotic extension field (e.g. via Risch decision procedure).
   - `Unsupported(String)`: The expression falls outside the implemented heuristics or algorithms, returning the input expression wrapped in an unevaluated noun form along with the explicit reason. Under no circumstances may an unsupported expression be marked as `Ok` or claimed to be proven non-elementary.
2. **Dynamic Verification Invariant ("Zero-Fake-Verification")**: No result may be labelled `verified: true` unless verified dynamically at runtime. For differential equations, the proposed solution must be substituted back into the original ODE and differentiated via `sym-core/src/diff.rs`, simplifying to `0` algebraically or vanishing within relative numerical tolerance across $\ge 5$ evaluation points. For definite integrals, results must be cross-checked against adaptive numeric quadrature. If verification fails or is not executed, `verified` must be `None` or `Some(false)`.
3. **Parser Precedence, Scientific Notation & Recursion Depth Bounds**: Operator precedence in `parse_maxima` and `parse_latex` must strictly bind exponentiation (`^`) tighter than unary negation (`-`), ensuring `-x^2` parses as `-(x^2)`. Parsers must tokenize standard scientific notation (`1e-3`). Both parsers and AST evaluators must enforce a strict recursion depth limit (e.g. 256), returning a structured `ParseError::RecursionLimitExceeded` rather than exhausting thread stack space.
4. **Thread-Level Compute Isolation & Owned Concurrency Permits**: All CPU-intensive CAS computations executed in web/API contexts must run on worker threads with explicit stack sizes, bound by wall-clock timeouts. Concurrency semaphore permits (`tokio::sync::OwnedSemaphorePermit`) must be moved directly into the blocking compute task so permits are released only when the thread terminates, preventing thread starvation and frozen worker accumulation under timeouts.
5. **Truthful Capability Reporting**: Documentation status tables, API descriptions, and WebUI palettes must strictly reflect implemented capabilities (`✅ Complete` vs. `◐ Partial`), explicitly listing known domain boundaries without claiming unverified algorithms (e.g., distinguishing between rational-root factoring and full Berlekamp-Hensel).
